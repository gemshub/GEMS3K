GEMS3K 5.2.0 · solver paths

What runs, and in what order

This page shows, for each calculation mode, which solver runs first. It shows what the solver tries when a calculation fails and when it stops. The same content as plain text is in SOLVER-PATH-GRAPH.md. To choose a mode and to see what each setting does, read the options guide. The glossary explains the special words.

Summary

You choose the mode

Put a value in NodeStatusCH before each call. GEMS3K does not change your choice. One exception: in a build without Optima, GEMS3K uses the GEMS3K IPM solver.

A failed try does not make the result worse

Each new try starts from the same inputs. If no try succeeds, you get the best attempt that keeps the element totals. Its status is BAD (pa_FailRescue). With the value 0, you get the first result without change.

GEMS3K counts all tries

The iteration count after the call includes each try.

Kinetics does not use the retry ladder

If the time step is more than zero, GEMS3K does not use the retry ladder after a failed call. The tries inside a solver and the rescue still run.

The modes

After these tries, each mode can go to the rescue (pa_FailRescue, on by default).

What each call does first

  1. It reads the temperature, the pressure and the bulk composition from the node. It checks that the temperature and the pressure are in the range of the data tables.
  2. It loads the previous result in the warm modes (SIA and SOP). SHP uses the previous result for its GEMS3K IPM part if a usable result exists. If no usable result exists, or if the warm attempt fails, SHP makes a cold start. All other modes prepare a new start.
  3. If kinetics is on, it does one kinetics time step.
  4. It holds back, for this call only, each species that is an exact copy of another species.
  5. If pa_DG is more than 1e-5, it scales all amounts to a fixed total. At the end, it scales the amounts back.

GEMS3K IPM Inside the GEMS3K IPM solver

The solver runs in AIA and SIA. It also runs as the first part of HOP and SHP.

  1. First guess. In a cold start, a simple linear calculation finds a set of start amounts. In a warm start, the solver uses the previous result. If the system has only pure phases, this step gives the final result. If the system has no aqueous, gas or sorption phases, the solver starts from the leveled solution (pa_IpmLevelStart). If this call fails, GEMS3K solves it again from the usual start.
  2. Mass balance fix. The solver changes the amounts until each element agrees with the bulk composition.
  3. Main descent. The solver lowers the Gibbs energy step by step until the steps are small enough. If the energy does not improve for 500 iterations (pa_IpmNoProgress), the descent stops and Optima finishes the result. If Optima fails, GEMS3K solves the call again without this stop.
  4. Phase check (pa_PC = 2, the default). It removes phases that must not be there. It adds phases that must be there. It removes very small amounts. It never adds a phase in a larger amount than the bulk composition can supply. If the phases change, steps 2 to 4 run again.
  5. Second mass balance fix. This step uses the final set of phases.
  6. Final checks. If an element does not agree with the bulk composition, the solver does one repair (pa_MbReproject, on). If the repair does not help, the solver gives the result and writes a warning in the log.
  7. Optima finish (pa_NativeOptimaFinish, needs a build with Optima). A solid can be left out of the result but still tend to form. Then Optima finishes the result. GEMS3K keeps the new result only if it is better. The descent can stop at its iteration limit, or it can fail to solve its equations. Then Optima finishes the result from that point.

A cold start can fail because the numbers grow without limit. Then the solver starts again one more time. It uses a simpler phase check. Then it stops.

Optima Inside the Optima solver

The solver runs in AOP and SOP. It also runs as the second part of HOP and SHP.

  1. First guess.
    • In AOP, a quick try comes first (pa_OptimaFastFirst, on). It is a short, plain solve with full steps. It stops early if the energy keeps going up or becomes very large. It stops early if its steps do not change anything. It stops early if its error does not improve after a jump in energy. Then the normal solve starts from the same inputs. If the quick try uses all its iterations but ends OK, GEMS3K keeps the result when no missing phase can form (pa_OptimaFastAcceptCut).
    • Cold start: a linear calculation puts the mass in as few species as it can. If this leaves almost no water, or leaves a mixed phase empty, GEMS3K corrects the guess first.
    • Warm start: GEMS3K uses the previous result. If the node was never solved, GEMS3K writes a warning and makes a cold start.
    • In HOP and SHP: the start is the result of the GEMS3K IPM solver.
    • Leveled start (pa_OptimaColdLevel, pa_OptimaLevelStart, on). It is only for the quick try and the first full attempt. The guess also uses the mixed phases. If the system has only solids and other mixed condensed phases, GEMS3K first finds which mixed phases form and what their compositions are. If no mixed phase forms, Optima only confirms this result. If mixed phases form, the finishing step first runs on that start. Optima then starts from the new point (pa_OptimaLevelFinish). If the smaller problem is not used, the start is the result of the linear calculation and its element potentials. Two copies of one solid solution start at different compositions.
  2. Smaller problem first (200 species or more, AOP and SOP). The solver solves with only the species that are likely to matter. Then it adds each species that it needs. If this step does not settle, GEMS3K drops it.
  3. Main solve.
    • It stops after 200 steps without progress (pa_OptimaStallWindow). A new try can then start sooner.
    • It stops when the energy and the error do not change at all for 20 steps (pa_OptimaFrozenCut). This stop is not in HOP and SHP.
    • On a warm call, the line search tries at most 5 step lengths (pa_OptimaLSWarmTrials).
    • On a warm call, an error can stay only on a solid solution that is almost gone. Then the solve stops and holds that solid at zero. The solver then finishes. The hold stays only if no absent solid tends to form. If a solid does tend to form, the solve continues from the point where it stopped (pa_OptimaTailDryOnly = 2).
    • For a system with a multisite solid solution, the solver first looks for a phase that must disappear. This look is short: 200 steps in a cold start, 25 steps in a warm start.
  4. Tries in the call. These tries run in this order. They run only while the result is not good: put the water back. Put back a mixed phase that became empty. Remove the vanishing phase of two identical mixed phases. Check each phase, add or remove phases, and repeat until nothing changes. As a last step, solve again without the early stops. After a stuck solve fails, the finishing step runs first on the point where the solve stopped. GEMS3K keeps its result if no phase tends to form (pa_OptimaFinishFirst).
  5. Finish. If Optima stops just short of the result, a final step finishes the job on the phases that Optima found (pa_OptimaFinish, on). It stops early if its error, its energy and its step size do not change for 15 steps (pa_OptimaFinishStall).
  6. Final checks. The solver checks if each element agrees with the bulk composition. It checks if a missing phase must form. It checks if the result meets the pH target and the Eh target. Before the checks, an element that only the floor amounts of its species hold gets its real amount back (pa_OptimaTraceRespread).
  7. Accept by direct check. Optima can fail its own stopping test. If the mass balance holds, and a direct test shows that no missing phase must form, GEMS3K accepts the result (pa_OptimaTpdAccept, on).
  8. Touch-up. An accepted result can have a small error in the element totals. The solver tries a small repair. It keeps the repair only if the repair helps. Then it sets absent phases to 0, by the same rule as the GEMS3K IPM solver (pa_OptimaZeroAbsent = 3).

Cap on one call (AOP and SOP, pa_OptimaCallCap, off by default). The whole call, with all its tries, can use only a set number of iterations. If a call fails and the cap is used up, GEMS3K repeats the call with the bulk composition changed by a very small amount. It does this up to pa_OptimaCapNudges times. Each repeat has a new cap. GEMS3K finishes a result from a repeat at the exact composition. If no repeat works, GEMS3K runs the call one more time without the cap. For this reason, the cap does not lose a result.

Dry-out path (optional, pa_OptimaDryOut, off by default). The water can run out in the main solve. Then the solve stops and GEMS3K takes the water phase out. The solver solves the solids alone. GEMS3K compares this result with a solve that keeps the water. It keeps the result with the lower energy. If the dry solve fails, the usual solve continues with the water back. GEMS3K does not use this path if an element can only be in the water.

Three settings act after the water is out. The tail stop (pa_OptimaTailStop, pa_OptimaTailStopWarm, pa_OptimaTailDryOnly) ends a solve whose energy does not change and whose remaining error is only on trace amounts. A phase stability check follows. pa_OptimaWaterKeep keeps a dry result that converged or that the tail stop ended. GEMS3K does not try it again with more water. With pa_OptimaTailDryOnly = 2 (the default), the tail stop also acts on warm calls.

Only the Optima modes can fix the pH or the Eh.

Hybrid HOP and SHP

  1. The GEMS3K IPM solver runs. In HOP it makes a cold start. In SHP it makes a warm start. If the node of SHP was never solved, the solver makes a cold start and writes a warning. The solver can stop because the energy does not improve (pa_IpmNoProgress). Then Optima starts from that point. It first starts warm. If that fails, it makes a cold start. If the solver starts from the leveled solution and fails, GEMS3K solves it again from the usual start.
  2. GEMS3K saves the result of this part.
  3. Optima runs and starts from the saved result.
  4. If Optima succeeds, you get its result. If Optima fails, GEMS3K puts back the saved result and the status is BAD. For this reason, HOP is never worse than the GEMS3K IPM solver alone.

The GEMS3K IPM part can fail. Then SHP first runs it again with a cold start. If there is still no result, Optima runs alone with a cold start, as in AOP. The iteration count is the sum of the two parts. GEM_IterationsHOP() gives the two parts separately.

After a failed call: the retry ladder

When a solver returns a failure, GEM_run() can try again from the same inputs. The steps run in this order. The ladder stops at the first success. If a step does not succeed, it gives back the result that existed before that step.

StepApplies toWhat it doesSetting (default)
1AOP SOP HOP SHP Solves again with the anti-stall step of the line search switched off. pa_OptimaLineSearch (1.5), pa_OptimaLSStallEscape (10)
2AIA After a failure with no result: solves from up to 4 compositions that are changed by a very small amount. The first that works is the warm start for the exact composition. pa_ColdRetryNudges (4)
3SOP SHP Solves again with a cold start as AOP. If it works, the status shows AOP. pa_OptimaColdRetry (2)
4AOP, and inside step 3 Makes one more cold start, from a better first guess that also uses the mixed phases. pa_OptimaCgSeed (1e-6)

If pa_OptimaColdRetry = 2, a warm Optima call that goes badly stops early. It goes straight to step 3. This is usually less expensive than the end of the warm try.

The rescue (pa_FailRescue)

A call can still end with an error or a BAD result. Then the rescue tries the call again in steps. It stops at the first step that succeeds. GEMS3K finishes each successful step at the exact composition with the normal settings.

StepWhat it does
1Solves warm from the previous result of the node.
2Solves at compositions that are changed by a very small amount.
3Goes in 8 steps from the previous result to the new composition (pa_RescueWalkSteps).
4Solves with looser settings.
5Solves with the other solver.
6Gives the best attempt that keeps the element totals, with a BAD status (only if pa_FailRescue = 2).

If a kinetic call has no result from any step, the rescue skips steps 4 and 5. If there is a pH target or an Eh target, GEMS3K keeps only an attempt that meets the target. GEM_rescue_step() tells you which step gave the result. 0 means the call itself.

How to read the result

StatusMeaning
OK_GEM_…The result passed all checks.
BAD_GEM_…There is a result, but it did not pass all checks. In HOP and SHP, this usually means that Optima failed and you have the GEMS3K IPM result.
ERR_GEM_…There is no result. All values that you read from the node are from before the call.

The status can name a different mode from the mode that you asked for. SIA changes to AIA after a new cold start. SOP and SHP change to AOP after step 3 of the ladder. After a rescue, GEM_rescue_step() is not 0. If the value is 6, the result is the best attempt and the status is BAD.

How to choose a mode

The full table is in the options guide. In short:

SituationMode
One calculationAIA — the fastest on almost all systems
A checked answerHOP — costs a little more than AIA, never worse
Solid solutions, melts, phase diagramsAOP or HOP
A series of small stepsFirst point: AIA or AOP. Next points: SIA, SOP or SHP
A series that crosses phase boundariesSOP or SHP, not SIA
Very little waterAIA or HOP

Without Optima

In a build without Optima, AOP, ROP and HOP run as AIA. SOP and SHP run as SIA. GEMS3K writes a warning in the log. The status then names the GEMS3K IPM mode.
