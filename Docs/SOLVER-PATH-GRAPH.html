GEMS3K 5.0.0 · solver paths

What runs, and in what order

For each calculation mode: which solver runs first, what it tries when something goes wrong, and when it gives up. The same content as plain text is in SOLVER-PATH-GRAPH.md; how to choose a mode and what each setting does is in the options guide.

The short version

You choose the mode

Put a value in NodeStatusCH before each call. GEMS3K never changes your choice, except in a build without Optima.

A failed try never makes it worse

Every extra try starts from the same inputs. If it does not succeed, you get the first result back unchanged.

Every try is counted

The iteration count after the call includes all tries.

Kinetics skips the outer retries

With a time step above zero, the retries after a failed call are skipped. The tries inside a solver still run.

The six modes

What every call does first

  1. Reads temperature, pressure and bulk composition from the node, and checks they lie inside the data tables.
  2. Loads the previous result (SIA, SOP). SHP uses a usable previous result for its GEMS3K IPM leg; if none is available or the warm attempt fails, it starts from scratch. All other modes prepare a fresh start.
  3. If kinetics is on, runs one kinetics time step.
  4. Holds back species that are exact copies of other species, for this call only.
  5. If pa_DG is above 1e-5, scales all amounts to a fixed total, and scales them back at the end.

GEMS3K IPM Inside the GEMS3K IPM solver

Used by AIA and SIA, and as the first part of HOP and SHP.

  1. First guess. From scratch, a simple linear calculation gives starting amounts. From the previous result, it reuses that. With only pure phases, this already gives the answer.
  2. Mass balance fix. Adjusts amounts so every element adds up to the bulk composition.
  3. Main descent. Lowers the Gibbs energy step by step until the steps become small enough.
  4. Phase check (pa_PC = 2, the default). Removes phases that should not be there, adds back phases that should, and cleans up tiny amounts. It never adds a phase in a larger amount than the bulk composition can supply. If phases changed, steps 2–4 run again.
  5. Second mass balance fix, on the final set of phases.
  6. Final checks. If an element still does not add up, one repair is tried (pa_MbReproject, on). If that does not help, the answer is returned with a warning in the log.

If a start from scratch fails because the numbers start to run away, it restarts once more with a simpler phase check before giving up.

Optima Inside the Optima solver

Used by AOP and SOP, and as the second part of HOP and SHP.

  1. First guess. From scratch: a linear calculation that puts the mass in as few species as possible, corrected first if it leaves almost no water or empties a mixed phase. From the previous result: reused; if the node was never solved, a warning is written and it starts from scratch. In HOP and SHP: the GEMS3K IPM answer.
  2. Smaller problem first (200 species or more, AOP and SOP). Solves with only the species likely to matter, then adds back any that turn out to be needed. If this does not settle, it is dropped.
  3. Main solve. Stops early after 500 steps without progress (pa_OptimaStallWindow), so a retry can start sooner. With a multisite solid solution it first takes a short look (200 steps from scratch, 25 from a previous result) to spot a phase that should disappear.
  4. Tries inside the call, in order, only while the answer is not good: put the water back; refill a collapsed mixed phase; drop the vanishing one of two identical mixed phases; check every phase and add or remove, repeating until nothing changes; and as a last resort, solve again without the early stops.
  5. Finish. If Optima stopped just short, a final step finishes on the phases it found (pa_OptimaFinish, on).
  6. Final checks. Do the elements add up? Should a missing phase form? Were the pH and Eh targets met?
  7. Accept by direct check. If Optima's own stopping test was not met but the balance holds and a direct test shows no missing phase should form, the answer is accepted (pa_OptimaTpdAccept, on).
  8. Touch-up. If an element does not quite add up, a small repair is kept only if it helps (pa_OptimaZeroAbsent = 2). With 1, species of absent phases are set to exactly zero.

Only the Optima modes can fix the pH or Eh.

Hybrid HOP and SHP

  1. The GEMS3K IPM solver runs: from scratch in HOP, from the previous result in SHP (from scratch, with a warning, if the node was never solved).
  2. Its answer is saved.
  3. Optima runs, starting from that answer.
  4. Optima succeeds: you get its answer. Optima fails: the saved answer is put back and the status is BAD. So HOP is never worse than the GEMS3K IPM solver alone.

If the GEMS3K IPM part fails, SHP first reruns it from scratch. If there is still no answer, Optima runs alone from scratch, as in AOP. The iteration count is the sum of both parts; GEM_IterationsHOP() gives them apart.

After a failed call: the retry ladder

When the solver returns a failure, GEM_run() tries again from the same inputs. The steps run in this order and stop at the first success. A step that does not succeed hands back the result as it was.

StepApplies toWhat it doesSetting (default)
1AOP SOP HOP SHP Solve once more with the line search's anti-stall step switched off pa_OptimaLineSearch (1.5), pa_OptimaLSStallEscape (10)
2AIA After a failure with no result: solve from up to 4 microscopically changed compositions; the first that works is the warm start for the exact one pa_ColdRetryNudges (4)
3SOP SHP Solve again from scratch as AOP; reported as AOP if it works pa_OptimaColdRetry (2)
4AOP, and inside step 3 Solve from scratch once more, from a better first guess that also looks at mixed phases pa_OptimaCgSeed (1e-6)

With pa_OptimaColdRetry = 2, a warm Optima call that is going badly gives up early and goes straight to step 3, which is usually cheaper than finishing the warm try.

Reading the result

StatusMeaning
OK_GEM_…The answer passed all checks.
BAD_GEM_…There is an answer, but not every check passed. In HOP and SHP this usually means Optima failed and you have the GEMS3K IPM answer.
ERR_GEM_…No answer. Values read from the node are left over from before the call.

The status can name another mode than the one asked for: SIA becomes AIA after a restart from scratch, and SOP or SHP become AOP after step 3 of the ladder.

Which mode to choose

The full table is in the options guide. In short:

SituationMode
One calculationAIA — the fastest by far on almost every system
A checked answerHOP — little more than AIA, never worse
Solid solutions, melts, phase diagramsAOP or HOP
A series of small stepsFirst point AIA or AOP, then SIA, SOP or SHP
A series crossing phase boundariesSOP or SHP rather than SIA
Very little waterAIA or HOP

Without Optima

In a build without Optima, AOP and ROP run as AIA, SOP as SIA, HOP as AIA and SHP as SIA, with a warning in the log. The status then names the GEMS3K IPM mode.
